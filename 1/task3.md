【产品级提示工程 · 页面三：数据展示页（稳定优先）】
页面角色定义（先定性）

这是一个只负责“如实呈现数据”的页面，
不是分析页、不是建议页、不是健康指导页。

它的唯一目标是：

让用户一眼看到：有没有数据、数据是不是最新、当前状态是否可信。

一、整体设计原则（比功能更重要）

稳定感 > 信息量

清晰 > 漂亮

数据真实感 > 图表炫技

禁止：

复杂分析

预测趋势

健康建议

情绪化文案（如“太棒了”“需要改善”）

二、页面整体结构（严格顺序，不得调整）

页面由 4 个层级模块 组成：

顶部：同步 / 刷新操作区

横幅卡片一：运动数据

横幅卡片二：睡眠数据

下方：基础生理数据卡片区

三、顶部：同步 / 刷新操作区
UI 结构

一个清晰的「同步 / 刷新」按钮

位置固定、易发现

不与数据卡片混在一起

行为规则

点击后：

进入加载状态

有明确反馈（如 loading / 禁用按钮）

同步中：

禁止重复点击

同步失败：

不弹异常技术错误

只提示“同步失败，请重试”

四、横幅卡片一：运动数据（主视觉区）
展示内容（不可删减）

步数（主）

卡路里

距离

布局规则

步数：

字号最大

视觉中心

卡路里 / 距离：

辅助展示

不与步数抢视觉

行为与状态

数据存在：

正常展示

数据为空：

显示“暂无数据”

不显示 0

不报错

五、横幅卡片二：睡眠数据（结构优先）
展示内容

总睡眠时长（主）

深睡

浅睡

视觉要求

使用比例或结构区分层级感

不使用复杂图表

不强调“好 / 坏”

状态规则

数据完整：

正常展示

数据缺失 / 未同步：

显示“暂无数据”

页面结构不塌陷

六、下方：基础生理数据卡片区（稳定区）
数据范围（示例级，不强制）

心率

血氧饱和度

血压

血糖

其他 SDK 明确、稳定提供的数据

⚠️ 原则：

SDK 不稳定 / 你不确定语义的数据，不要展示。

单卡片结构（强约束）

每一个指标 必须是独立卡片，包含：

指标名称

当前数值

单位

禁止：

多指标塞进一张卡

单位省略

用颜色暗示健康风险

数据状态规则

有数据：

正常显示

无数据：

显示“暂无数据”

不显示 0

不展示占位假数据

数据集情况（非常重要）

如果 SDK 返回的是 数据集合（数组 / 多条记录）：

必须 完整枚举展示

不擅自取“最新一条”

不做平均 / 汇总

保证顺序清晰

七、蓝牙与同步状态约束（继承前页）

蓝牙未连接：

页面可进入

数据只读

同步按钮不可用

蓝牙异常断开：

页面不报错

不清空已有数据

同步按钮自动禁用

八、异常与边界处理（必须覆盖）

同步中断：

恢复到上一次数据状态

数据解析失败：

单卡片显示“暂无数据”

不影响其他卡片

页面切换：

不自动触发同步

九、AI 执行边界（再次锁死）

你只能做：

数据展示

状态区分

UI 稳定性保障

你不能做：

数据分析

健康判断

趋势预测

智能建议

十、阶段结束规则

👉 到此为止，必须停下

当前阶段完成标准：

页面结构清晰

数据状态不混乱

空数据不让用户困惑

不因单项异常导致页面崩坏
